# 人工智能社官网：运行与维护

## 1. 项目组成

本项目直接使用仓库中的 frontend/、backend/，无需再创建项目外层目录。

- frontend：Vue 3、TypeScript、Vite、Pinia、Vue Router、Axios、Element Plus、wangEditor 5。
- backend：Java 21、Spring Boot 3.5.16、Spring Security、MyBatis-Plus、Flyway、MySQL。
- deploy：Docker Compose、Nginx、环境变量模板、备份恢复脚本。
- docs：运行维护、接口和实现约定。

只初始化“首页、关于我们、加入我们”三个固定页面。所有缺失人物、活动、项目和荣誉均明确显示待补充，没有虚构的成果或个人资料。原 README.md 与 TechStacks.md 保留为需求依据。

## 2. 本地开发

依赖：JDK 21、Maven 3.9+、Node.js 22.12+（推荐 24 LTS）、MySQL 8.4。

先用数据库管理员执行（密码自行替换）：

```sql
CREATE DATABASE ai_club CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'ai_club'@'localhost' IDENTIFIED BY '自行设置的数据库密码';
GRANT ALL PRIVILEGES ON ai_club.* TO 'ai_club'@'localhost';
```

PowerShell 启动后端：

```powershell
$env:DB_PASSWORD = '自行设置的数据库密码'
$env:BOOTSTRAP_USER = 'club-admin'
$env:BOOTSTRAP_PASSWORD = '自行设置的初始密码，至少12字符'
cd backend
mvn spring-boot:run
```

首次启动执行 Flyway 迁移，并创建一个超级管理员。数据库已有账号时，初始化变量不会重置账号密码；可以从部署环境移除初始密码。本地上传目录默认 backend/data/uploads，请勿删除。

无需 MySQL 的临时预览（内存数据在退出后清空，不能用于正式运营）：

```powershell
cd backend
mvn spring-boot:test-run -Dspring-boot.run.main-class=cn.aiclub.PreviewApplication
```

预览账号为 test-super，密码为 a-test-password-12345，仅存在于测试源码。生产 jar 不包含此启动类、测试配置或 H2。

另开终端启动前端：

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

打开 http://localhost:5173，登录页为 /login，后台为 /admin。Vite 将 /api 代理到 localhost:8080，同源 Cookie 与 CSRF 可正常工作。不要直接用文件协议打开 index.html。

首次安装也可使用 npm.cmd install。仓库生成 package-lock.json 后优先使用 npm.cmd ci。

后端公开端口默认为 8080。数据库地址可通过 DB_URL、DB_USER、DB_PASSWORD 指定，密码没有内置默认值。

## 3. 构建与验证

```powershell
cd backend
mvn test
mvn package
```

后端测试使用 H2 的 MySQL 兼容模式，执行同一份 Flyway 初始化脚本，覆盖真实 HTTP 安全过滤器、发布流程、草稿图片隔离、富文本清洗、错误上传、CSRF、账号停用和密码重置后的会话失效。上线前仍应使用真实 MySQL 8.4 完成联调和备份恢复演练，H2 无法代替 MySQL 的全部行为。

```powershell
cd frontend
npm.cmd run build
```

前端构建包括 TypeScript 检查，输出 dist。可使用 npm.cmd run preview 检查构建产物；preview 不代理后端，完整联调使用开发服务器或 Nginx。

受限环境中若 Maven 默认缓存不可写，可显式使用工作目录缓存：

```powershell
mvn -Dmaven.repo.local=../.cache/m2 test
```

## 4. Docker Compose 部署

先启动 Docker Desktop / Docker Engine。以下命令在 deploy/ 下执行：

```powershell
Copy-Item .env.example .env
# 编辑 .env，将所有示例密码替换成独立随机密码。
docker compose up -d --build
docker compose logs -f backend
```

默认只绑定 127.0.0.1:8088，用于本机验证或同机 HTTPS 网关。数据库和后端不映射宿主机端口。MySQL 命名卷保存数据库，uploads 卷保存图片；docker compose down 保留卷，禁止在没有备份时使用 down -v。

生产上线：域名解析到服务器，通过 HTTPS 网关反向代理到 http://127.0.0.1:8088，设置正确证书，并将 .env 中 COOKIE_SECURE=true 后重建 backend。可以使用下面的宿主机 Nginx 模板：

```nginx
server {
    listen 80;
    server_name club.example.edu;
    return 301 https://$host$request_uri;
}
server {
    listen 443 ssl;
    server_name club.example.edu;
    ssl_certificate /etc/letsencrypt/live/club.example.edu/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/club.example.edu/privkey.pem;
    client_max_body_size 11m;
    add_header Strict-Transport-Security "max-age=31536000" always;
    location / {
        proxy_pass http://127.0.0.1:8088;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

HTTPS 网关所在服务器之外不要开放 8088。部署配置和真实证书不要提交到仓库。生产中不打开 OpenAPI UI；本地设置 API_DOCS_ENABLED=true 后，已登录管理员可以访问后端 /swagger-ui/index.html。

Nginx 已配置 Vue history 刷新回退、上传大小限制、内容安全策略和基本响应头。使用站内导航或直接刷新详情页、后台编辑页均应正常。

## 5. 日常内容维护

1. 以个人管理员账号登录，选择“新建内容”。
2. 选择新闻、活动、项目成果或师生资料，填写标题、摘要、正文与分类。
3. 上传封面、正文图片和相册。仅允许有效 PNG/JPEG，最大 10MB、2400 万像素；服务端重新编码为 JPEG，长边最大 2400 像素，透明部分转白色。
4. 资料未知时写“待补充”；公众号文章保留来源、原文链接和图片署名。个人照片需获得公开许可。
5. 保存草稿并预览。预览必须登录，未发布内容与仅被草稿引用的图片无法匿名访问。
6. 点击“保存并发布”。发布后官网立即从 API 读取新内容。
7. 已发布内容保存修改会直接更新官网；如需先暂存修改，请先下架成为草稿。第一版没有同一内容的独立“公开版本 + 待审版本”。
8. 下架后内容与其独占图片不再公开；移入回收站可恢复，恢复后保持草稿，需再次发布。第一版不提供永久删除按钮。

首页：在“页面设置”的 home 页面维护主标题、摘要和精选图；摘要用作首页主视觉标题。项目勾选“首页推荐”，动态勾选“置顶”，通过排序数值调整顺序。about、join 为固定页面标识，不可改名或移入回收站；可以修改标题、正文、图片及 join 的外部报名链接。老师和成员可填写届别、职务，归档后仍可在公开成员列表查看；需要隐藏时使用下架。

活动填写起止时间、地点、状态；结束时间早于当前时间时前端优先显示“已结束”。日期输入按本地时间显示，社团运营约定使用北京时间，服务器设为 Asia/Shanghai。

图库不开放任意外链图片插入，请先上传本站。编辑器中的自定义样式可能经服务端清洗简化；正文保留标题、段落、表格、列表、引用、代码、链接和图片。

并发编辑通过 version 检查，冲突时提示刷新；刷新前请复制未保存正文到安全位置。内容及图片响应不允许缓存，降低下架后旧缓存继续显示的可能。

## 6. 账号交接

超级管理员为每位维护成员创建个人账号，并安全地交付初始密码。成员首次登录后自行修改密码；密码长度 12–72 字符，使用 BCrypt 哈希，不记录明文。

离任时先创建并验证接任人的超级管理员账号，之后停用离任账号。系统不允许超级管理员停用或降级自己，并保留至少一个可用超级管理员。角色变更、停用、重置密码、修改密码会通过认证版本使旧会话在下一次请求时失效。会话超时 30 分钟；后端重启后重新登录。

忘记密码由其他超级管理员在“账号管理”中重置。若所有超级管理员凭据丢失，需由服务器维护人员在停服和备份后，通过受控数据库操作恢复；不要删除全表或将真实密码写入 SQL 仓库。

## 7. 备份与恢复

在服务器安装 POSIX sh（Linux 默认具备；Windows 可用 WSL），Docker 命令需可用。脚本从 deploy/ 目录运行，传入的相对路径按该目录解析。

```sh
sh backup.sh ../backups/2026-11-09
```

备份期间暂停后端写入，打包 SQL 与图片，完成或失败后恢复后端运行。请检查退出码、两个文件非空，并保存到独立磁盘 / 受控异地存储。备份包含个人信息和密码哈希，限制读取权限并加密保管。可通过服务器系统定时器每日执行，按学校策略保留多个历史版本。

恢复前先做当前状态备份，核对目标环境及备份文件：

```sh
sh restore.sh ../backups/2026-11-09 --confirm
```

恢复会覆盖数据库内容，将图片包解压到上传卷；失败时后端保持停止，检查错误并重新恢复，确认成功后再启动。额外残留的旧图片没有数据库引用时无法公开读取。恢复后核对：首页、详情、相册、管理员登录、发布及下架。定期在隔离环境演练恢复。

## 8. 版本维护与范围

依赖版本在 pom.xml 和 package.json / package-lock.json 锁定。Spring Boot 3.5.16 属于需求指定的 3.x 系列。2026-11-09 核对官方项目数据 https://spring.io/page-data/projects/spring-boot/page-data.json ：3.5.x 开源支持于 2026-06 结束，企业支持期限为 2032-06。因此生产部署 3.5 系列需要确认组织的商业支持资格；若没有，应在上线前评估迁移到受开源支持的主版本（例如 4.1.x，官方开源支持至 2027-07）。本实现按已有技术约定保留 3.x，未擅自改变主版本。支持窗口和补丁公告需持续复核，参考 https://spring.io/projects/spring-boot#support 。

升级先在独立环境验证 Flyway、会话、前后端构建、图片和备份恢复；不要修改已执行过的 Flyway 迁移，新建 V2、V3 脚本。

基础 SEO 提供页面标题、摘要和独立 URL；当前是 Vue SPA，没有 SSR / 静态预渲染，搜索引擎和社交平台抓取详情正文与独立分享卡片的能力取决于其 JavaScript 支持。若后续需要稳定的公众号分享摘要或搜索收录，增加服务端预渲染。

第一版不包含普通用户注册、站内报名、全文搜索、评论、论坛、AI 问答、对象存储或多实例部署。图片采用引用鉴权；同一张图片如果也被已发布内容引用，本来就属于公开图片，不应用它保存额外未公开资料。
